# Планировщик задач

Веб-приложение для разовых и повторяющихся задач. Сервер на Go раздаёт веб-интерфейс и HTTP API, а SQLite хранит расписание в файле.

- Создание, редактирование, удаление и завершение задач
- Поиск по заголовку, комментарию или дате в формате `ДД.ММ.ГГГГ`
- Повторение каждые 1–400 дней или ежегодно. При завершении разовая задача удаляется из списка, а повторяющаяся переносится на следующую дату

Проект использует Go 1.24.4, `net/http`, `database/sql` и драйвер `modernc.org/sqlite`.

## Запуск

Установите Go 1.24.4 или новее. Из корня проекта выполните команду ниже

```sh
go run .
```

Откройте [http://localhost:7540](http://localhost:7540). При первом запуске приложение автоматически создаст файл `data/scheduler.db`, таблицу задач и индекс по дате. Для остановки нажмите `Ctrl+C`. Задачи сохраняются в файле базы.

Чтобы изменить порт, задайте переменную окружения `TODO_PORT` перед запуском. Например, в PowerShell

```powershell
$env:TODO_PORT = "8080"
go run .
```

### Запуск в Docker

При установленном Docker соберите образ и запустите контейнер

```sh
docker build -t go-scheduler .
docker run -d --name scheduler -p 7540:7540 -v scheduler_data:/app/data go-scheduler
```

Приложение будет доступно по адресу [http://localhost:7540](http://localhost:7540). База сохраняется в томе `scheduler_data`. Чтобы использовать другой внешний порт, замените `7540:7540` на `8080:7540`.

Для остановки выполните `docker stop scheduler`, для повторного запуска — `docker start scheduler`.

## HTTP API

| Метод | Маршрут | Действие |
| --- | --- | --- |
| `GET` | `/api/tasks` | Получить до 50 задач, отсортированных по дате. Параметр `search` ищет по тексту или дате |
| `POST` | `/api/task` | Создать задачу |
| `GET` | `/api/task?id=1` | Получить задачу по ID |
| `PUT` | `/api/task` | Обновить задачу. ID передаётся в поле `id` тела запроса |
| `DELETE` | `/api/task?id=1` | Удалить задачу |
| `POST` | `/api/task/done?id=1` | Отметить задачу выполненной |
| `GET` | `/api/nextdate` | Рассчитать следующую дату по параметрам `date` и `repeat`. Параметр `now` задаёт дату отсчёта |

При создании и обновлении задачи передавайте JSON с обязательным полем `title` и полями `date`, `comment` и `repeat` по необходимости. Дата в API передаётся в формате `ГГГГММДД`. Если дату не указать, сервер подставит сегодняшнюю. Примеры правил повторения — `d 7` для интервала в семь дней и `y` для ежегодного повторения. Пустое правило задаёт разовую задачу.

## Тесты

**Тесты очищают таблицу задач в `data/scheduler.db`.** Если в базе есть нужные данные, перед тестированием остановите приложение и сохраните копию этого файла.

Запустите приложение командой `go run .`, затем во втором терминале из корня проекта выполните

```sh
go test ./... -count=1
```

Тесты обращаются к работающему серверу и тому же файлу SQLite, создавая задачи для проверок. Используйте одинаковое значение `TODO_PORT` в обоих терминалах, если меняли порт.

В `tests/settings.go` уже задан путь `DBFile = "../data/scheduler.db"` и включён поиск через `Search = true`. При запуске через Docker файл базы хранится в томе контейнера. Для описанного прогона тестов используйте запуск через `go run .`.

Тесты проверяют веб-интерфейс, работу с базой, операции с задачами, поиск и расчёт повторений. GitHub Actions при каждом push проверяет раздачу статических файлов.
